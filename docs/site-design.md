# 《再来一次》站点设计文档

v1.0 · 页面、交互与实现约定｜2026 年 10 月 30 日｜设计稿，尚未实施

依据：《再来一次》v0.5 方向文档，以及《游戏进程与事件策划案》v1.0。本文件负责页面和交互，不重复完整事件内容。它描述下一版站点，不代表当前成人职业版本已经重做。

这次的站点不是数值仪表盘，而是一个能让人静下来读、做出选择、看见时间往前走的人生现场。首要目标是让用户在手机上随时看得到当前事件，并清楚知道自己还能怎样操作。

# 一、产品与设计边界

- 游戏名统一为《再来一次》。首页文字建议：“从记事的那年开始，过一段不同的人生。”不使用旧称号、成绩排行和重开刷高分的引导。

- 第一访问无需登录。名字随机、不可编辑；从三个出身中选一个开始。继续已有存档、阅读旧回顾和导入备份均有明确入口。

- 事件是视觉中心。信息详情收进轻量入口，不把关系、工作、家庭、世界指标全部摊在事件上方。

- 不展示未选路线和“如果当初”。出身选完后另外两张不再出现；人生回顾中也不列它们。

- 提供完整的无伴侣、无子女、非大学、经营和自由职业页面状态，不把某种生活显示成待补齐的空格。

- 保留已经确认的交互：事件区少内容时小高度、到上限才内部滚动；信息面板不自动暂停；关键选择暂停；选择即时高亮；万元自由输入与单项卖出。

# 二、站点页面与入口

| 页面／区域 | 内容 | 进入与离开 |
| --- | --- | --- |
| 首页 | 一句话介绍、开始新人生、继续、我的回顾、导入、玩法说明 | 默认入口；已有进度优先显示继续 |
| 出身选择 | 随机姓名、年龄说明、三张生活描写卡、确认按钮 | 开始后进入；同一未开始人生刷新不重抽 |
| 游戏主界面 | 人物年龄、六类状态摘要、事件区、生活入口、时间控制 | 确认出身后进入；可暂停、导出或重开 |
| 信息面板 | 重心、学习／工作、人物关系、财务、消费、记录与设置 | 手机抽屉／底部面板；电脑右侧面板 |
| 关键事件 | 场景、人物、2～4 个选项、条件与费用 | 剧情实际走到此处才出现；必须明确选择才能推进 |
| 年度理财计划 | 持仓、资金、草稿、确认与本年状态 | 理财入口；一次计划可配置多种资产 |
| 人生回顾 | 实际时间线、重要人物、时间分配、取向描述与自述 | 真实终局；不是普通年份的结算页 |
| 分享预览 | 选择片段、隐藏细节、图文卡、链接与保存 | 回顾页；不默认公开所有财务与健康信息 |
| 历史回顾／旧版进度 | 按时间浏览；版本说明和导出 | 本设备保存，不排名、不显示收集率 |

建议采用简单的页面状态路由；分享结果使用稳定地址和明确版本。首页、当前人生、旧版回顾和他人分享不可互相覆盖本地自动存档。页面结构不要求为了查看面板频繁切整页。

# 三、首页

## 3.1 首次访问

从上到下：小型站点名 → 标题与一句话介绍 → “开始一段人生”主按钮 → “玩法说明／导入存档”次入口 → 简短的三句玩法说明 → 必要的统计与隐私信息。首页不先列所有职业、全部数值或长篇规则。

建议首页文案：
再来一次
从记事的那年开始，过一段不同的人生。
日子会一件件经过。遇到需要拿主意的事，就停下来选。
[开始一段人生]

## 3.2 有进度时

- 主入口改为“继续这段人生 · 28 岁”，下方显示人物姓名与上次保存时间。次入口是“开始新的人生”。不要让用户误以为每次打开都需要重来。

- 点击新人生后说明会替换当前自动存档，并提供导出和取消。已有回顾不随重开清空；新的角色不继承属性和解锁。

- 保留旧版进度时显示“有一份旧版人生，可继续查看或导出”。不能悄悄把成年角色转成六岁，也不把用户旧存档作为坏数据删除。

## 3.3 玩家数量

有真实服务端时，可显示“已有 N 位玩家开启人生”，附简短统计口径；按匿名浏览器标记去重、从功能上线开始，不叫实时在线人数。没有统计服务时，隐藏该数字或说明测试版未启用，不能编造热闹人数。统计不可用不妨碍开始游戏。

# 四、出身三选一

页面顶部说明：“这一生，从这里开始。”名字只读显示，起始年龄建议 6 岁。三张卡只写家庭与生活环境，不展示财富、能力加成、资源档、稀有度或推荐标签。

| 步骤 | 页面反应 | 保存规则 |
| --- | --- | --- |
| 生成候选 | 三张不重复描写；后台至少涉及两档资源条件 | 生成即保存候选和种子，刷新保持一致 |
| 点选卡片 | 立即加边框与选中标识，aria-pressed 同步 | 仅保存候选意向，尚未开始 |
| 确认出身 | 进入第一段人物与家庭介绍 | 只写入被选出身的实际事实 |
| 进入人生 | 另两张卡从界面、历史和分享中消失 | 底层只为重载保护保留必要事务状态，不把未选内容送入人生回顾 |

- 手机三卡纵向排，第一屏可看见至少一张完整卡和后续卡的提示；电脑三列同等宽度。卡片篇幅相近，不能把某一种出身写得明显更动人。

- 点卡片不立即开局，主按钮为“从这里开始”；未选时按钮不可用，并用文本说明“先选一个出身”。

- 没有换一批、抽到好出身或重抽倒计时。返回、刷新或短暂断网不更换候选。真正开始新人生要经过独立重开流程。

# 五、游戏主界面

## 5.1 手机布局

- 顶栏：站点名、更多菜单。不要在标志旁再放没有意义的装饰箭头。

- 人物行：姓名、当前年龄、当前学习／工作或居住事实。年龄是主轴，不显示“完成了人生 60%”或预知寿命的进度条。

- 状态摘要：健康、心情、可用金钱、关系、能力、声誉。用两行紧凑布局，可点开详情；压力数值不常驻。

- 事件区标题与当前状态：“日子继续”“有件事需要你决定”“已暂停”。这是最主要的阅读区域。

- 生活入口：重心、学习／工作、身边的人、钱与消费；按年龄换内容。没有资格的产品显示开放条件，不把当前能查看的信息一起禁用。

- 时间工具条：暂停／继续、下一件事、阅读速度。可在事件区底部保持可达，不遮住正文和选择按钮。

- 其他内容在面板内查看；不把年度账本、曲线和全部家庭信息继续排在事件之前。

## 5.2 电脑布局

中间事件区占主体宽度约 60%～70%，左侧为人物与精简状态，右侧详情按需展开。建议总内容宽度上限约 1200px，事件正文宽度控制在 600～760px。电脑不是把手机卡片逐个拉长，也不同时打开三个详情列。

## 5.3 信息层级与阶段变化

| 阶段 | 主身份文案 | 主要入口 |
| --- | --- | --- |
| 童年 | 某校在读／和家人共同生活 | 课后安排、兴趣、家人朋友、零用钱 |
| 少年 | 当前教育或训练状态 | 学习与兴趣、朋友、家庭协商、支配的时间 |
| 成年 | 实际岗位／接单／经营／学习／暂未就业 | 工作重心、关系、理财、消费与责任 |
| 老年 | 真实工作与生活状态 | 日常安排、联系的人、住处与照护、财务 |

职业变动即时更新身份和收入说明。离开岗位后撤回业务／公共资金权限；不能因为出生在小店就永远显示店主，也不能给退休者继续显示全职工资。

# 六、事件阅读窗口

- 高度规则：内容少时自然高度，不设置占满半屏的最小空白；内容增多到视口允许上限后 overflow-y:auto。建议手机上限约 50%～60% 可用视高，电脑约 60%～70%，最终由真机测试决定。

- 新事件在顶部；正文一般 1～3 段，日常可以只有一句。年龄作为左侧或上方时间标识，重大节点与普通日常使用克制的视觉差异。

- 玩家正在读旧内容时，保存滚动锚点；顶部显示“有新记录”，点击回最新。只有在最新位置时自动保持新记录可见。

- 默认按文字长度保留阅读时间，可沿用约 6.5～14 秒的范围再测试。允许调速与手动推进，不把“必须读多久”变成倒计时压力。

- 同年事件逐条进入视野，不一次性填满；到需要选择的实际节点才弹窗。年末账本在本年选择和安排之后显示，避免先知道全年结果再选。

- 历史展开也在有限高度窗口中浏览，可按年龄定位；“翻全部”不把整个页面恢复成无限长。键盘可聚焦事件区滚动。

# 七、关键选择弹窗

结构：年龄和情境说明 → 场景标题 → 具体正文 → 必要的当下资源信息 → 2～4 个同等视觉权重的选项 → 查看自身状态／稍后决定入口。不显示最佳选择、绿色正确选项或红色错误选项。

| 交互 | 必须表现 |
| --- | --- |
| 事件到来 | 先保存进度与面板草稿，再暂停；焦点进入弹窗 |
| 选择可用 | 整张选项卡可点击，点一次提交；处理中禁用重复提交 |
| 有门槛 | 说明具体缺现金、资格、人物或条件；至少有一项可以进行 |
| 选择完成 | 立即给出选中反馈，再显示当下结果；未选选项消失 |
| 选择后的推进 | 结果至少留出一个阅读节拍，再继续剧情，不能一闪而过 |
| 查看自己情况 | 选择保持待处理，时间仍暂停；可查状态，再回同一事件 |
| 关闭或按 Esc | 只收起，不代选；保留“继续决定”入口，仍不推进 |
| 刷新／离开 | 恢复同一个未完成事件，不再抽一个、不重复结算 |

选项写做法和当下已知的费用、时间与条件。后台状态变化与延迟影响不全量写成“+8、−3”的攻略；多年后的精确剧情不预告。选择数量超过四个时拆为有上下文的后续，而不是缩小字体塞下五六项。

# 八、信息面板与实时状态

手机采用底部／侧边面板，桌面采用右侧详情；同一时刻保持一个主要信息面板。面板默认不使已运行的剧情暂停，顶部如实显示“时间继续”或“当前已暂停”，不能始终写死一种状态。

| 面板 | 内容与操作 | 状态更新要求 |
| --- | --- | --- |
| 生活重心 | 当前可用的时间安排、具体影响说明 | 点击后立刻高亮、更新说明和存档；不用关闭重开才生效 |
| 学习／工作 | 当前路径、资格、排班、收入／经营情况 | 岗位离开、权限失效后立即改写，不保留可执行的旧按钮 |
| 身边的人 | 真实人物、联系状态、共同经历、可讨论事项 | 人物状态来自当前人生，不生成模板化“大学室友”给没上大学的人 |
| 钱与消费 | 现金、持仓、资产、负债、持续账单和消费记录 | 余额变化刷新可见数据，不能保留一组旧金额到关闭后才更新 |
| 年度安排 | 当前年度草稿与已确认安排 | 跨年不丢输入；提交时验证年份、条件和余额 |
| 记录／说明 | 已发生事实、玩法说明、导入导出 | 回忆与多年回响分别记录，不把回忆当成因果已实现 |

更新机制建议：面板显示从同一状态源读取；选中项、余额、条件标签和外部摘要一起刷新。输入中的文本不被每条新事件重置。年度变化时保留草稿并提示重新核对，禁用失效提交，不直接关窗。

# 九、年度理财与消费面板

## 9.1 财务总览

顶部明确“可用现金”，下方分别展示金融持仓、住房资产、个人欠款、经营资金与经营欠款。童年只显示个人零用钱和与当前决策有关的家庭可承担条件，不将父母全部财产显示成玩家余额。

## 9.2 年度计划的表单

- 显示当前年度、是否已确认本年主动计划，以及“草稿尚未执行”。一次计划内可同时处理多项资产，不能把每次输入金额都算作一次调整。

- 每项有持有金额、买入输入、部分卖出输入和“清仓这一项”。单位万元，支持最多四位小数（1 元），手机使用小数键盘。

- 显示预计执行后现金、费用和剩余持仓。买卖不在输入时立即执行，由“确认本年计划”统一提交；持有不强制操作。

- 计划内可使用本次卖出所得买入其他资产；按统一报价快照和固定结算顺序执行，不能因按钮顺序造成凭空收益或误报资金不足。

- 非法数值、超持仓、现金不足和资格不符在对应输入旁说明；保留其他正确草稿。确认必须原子执行，不能一半买入成功、一半失败。

- 本年已经确认后仍能查看，清楚显示下次可调整的时间；必要事件的应急变现是单独入口与记录，不开放第二次主动加仓。

- 关键事件尚未到达时，不因引擎预先准备了一个候选事件而禁用全部理财查看。真正正在等待选择时，仍可查账；与事件冲突的交易明确说明需先完成当前决定。

## 9.3 消费与持续费用

按住处、交通、学习、照护、兴趣与相处展示当前可用安排。每项说明一次性费用、年度费用、生效时间、承担账户和占用时间。确认前显示将增加的固定账单，不用“升级”暗示更贵就更好。已选择的长期安排不能重复购买叠加效果。

存在必要开支与现金不足时，提供当前制度下实际可行的协商、变现、借款或调整方案，不让玩家在一个“余额不足”页面永久卡死。贷款申请与金融买入是不同流程。

# 十、人物关系与多年回响的呈现

- 家人、朋友、伴侣三类只是导航，内部是具体人物；没有伴侣显示“目前没有伴侣关系”，不是红色 0 分或催促成家的空状态。

- 人物详情显示实际相遇、共同经历与当前往来，不预知对方寿命、下一步决定或隐藏成功率。对方有自己的意愿，不是花钱加满的一根条。

- 多年回响出现时，正文让玩家理解早年积累、地点、信任、债务等如何影响当下；不强制每次弹出“当年的正确选择得到回报”。

- 可以在已发生记录里提供“相关经历”入口，只链接实际发生的起因和后续；不开放尚未发生的因果树，也不显示没选的其他分支。

- 单纯看到旧照片或想起往事标为日常／回忆；真正改变当前条件的历史影响才计入回响。后台数据需可追溯，前台无需暴露任务排期。

# 十一、终局、回顾与社群分享

## 11.1 生命收束

进入真实终局时停止年度推进与交易，处理最后一段叙事，再进入回顾。最后一天只影响文字，不加减关系和健康；突发事件没有告别空间时不补造未发生的告别。

## 11.2 人生回顾页

- 首屏：姓名、实际年龄范围和一句事实摘要，主标题可为“这一生的记录”。不授予称号，不标高分结局。

- 时间线：按年龄展示真实关键节点，默认少量摘要，可展开已经发生的具体内容。

- 重要的人：显示实际在场人物及关系走向，包含后来联系减少、离开或离世的人。

- 时间分配：展示记录可支持的近似比例，注明游戏内估算；没有数据不编图。

- 取向描述：用几句不分高低的表达，不做 MBTI 称号、排名雷达或“你更适合什么人生”。

- 可选自述：玩家写一句话，可留空。它是自我表达，不改角色姓名，也不由系统打分。

- 出口：分享这段经历、保存回顾、导出备份、开始新人生。没有收集进度和“再刷一次获得更好称号”。

## 11.3 分享预览

默认选择 3～5 条已发生片段和玩家自述，玩家可改选、隐藏资产与疾病等细节；先预览，再生成链接或图片。卡片使用《再来一次》、人物姓名与生活片段，二维码指向实际当前托管域名，不能在 GitHub 版继续指向无法访问的旧域名。

- 区分“只分享选定片段”与“分享完整回顾”。只在卡片上隐藏但仍把完整资料编码进链接，不算真正隐藏。

- 静态托管可把选定的回顾快照编码进分享链接；提示任何获得链接的人可读，无后台时不能承诺随时撤回。自述和人物内容按不可信输入转义。

- 若链接过长，图片二维码可指向已选片段的精简快照；完整回顾另行导出。二维码旁如实说明打开的内容，不悄悄退化成与人物无关的新游戏。

- 他人回顾以只读访客模式显示，不能写入自己的自动存档。开始新人生需明确操作，不误触覆盖进度。

# 十二、视觉与可访问性

| 要素 | 建议规格 | 目的 |
| --- | --- | --- |
| 整体风格 | 暖白纸面、深灰绿正文、克制的细线和留白 | 亲近、可读，不像行政报表或金融终端 |
| 配色 | 背景 #F5F2E9；纸面 #FFFEF8；正文 #263B31；辅助 #667065；强调 #365B4C | 需要实测对比度；不把所有加减映射成正确与错误 |
| 正文 | 手机 15～17px，行高约 1.7～1.9；桌面约 16px | 长时间文字阅读；不用 10px 小字堆信息 |
| 标题 | 主页面标题 24～32px，事件标题 20～24px | 避免标题占满第一屏 |
| 点击区域 | 主要按钮和可选卡触控高度至少约 44px | 手机可操作；关闭按钮也应好点 |
| 选择状态 | 边框＋背景＋文字标识，aria-pressed 同步 | 不只依赖颜色；选后即时反馈 |
| 提示 | 费用、条件与错误靠近相关控件 | 不用底部一闪而过的 toast 承担所有信息 |
| 字体与资源 | 优先系统中文字体，本地静态资源 | 不依赖境外字体 CDN 才能读正文 |
| 动画 | 轻量出现、无闪烁；支持减少动态效果 | 不打断阅读；按系统偏好关闭移动动画 |

键盘与读屏：可聚焦事件滚动区；弹窗焦点管理、关闭返回触发点；图表附文字摘要；时间状态有文本。新事件的读屏播报避免每次重读整个历史列表。终局和关键选择不能只通过颜色通知。

# 十三、状态、异常与保存

| 情况 | 页面处理 | 数据要求 |
| --- | --- | --- |
| 自动保存成功 | 轻量显示最近保存状态，不反复挡住剧情 | 每次已提交选择持久化，未结算事件有独立 ID |
| 浏览器存储失败 | 明确提示未保存，立即提供导出 | 不虚假写“已保存” |
| 刷新／后台回来 | 恢复人物、事件进度、未完成选择和草稿 | 不重复扣费，不自动快进 |
| 网络断开 | 已加载的游戏可继续；统计和分享网络操作单独说明 | 不把统计失败当游戏失败 |
| 导入错误 | 展示版本／格式原因，保留当前进度 | 先验证再替换；损坏文件不覆盖 |
| 新旧版本不同 | 提供旧版只读回顾、导出和新开局 | 新引擎独立存档，不强制迁移旧角色年龄 |
| 统计接口不可用 | 隐藏数字或显示暂不可用 | 不降级成虚构随机人数 |
| 事件无可选项 | 提供当前实际可行的兜底并记录待修复场景 | 不能要求用户清档解决设计死锁 |
| 分享链接无效 | 说明无法读取，提供回首页 | 不覆盖自己的当前人生 |
| 重开取消 | 回到原位置及待处理事件 | 原进度和草稿保持不变 |

# 十四、实现与部署约定

建议保留“本地游戏引擎＋静态界面＋可选服务端”的结构。内容数据、人生状态、叙事队列和界面视图分离；同一状态只维护一份，避免外面余额更新而弹窗仍显示旧数字。本站点设计不要求先引入复杂账户系统。

| 层 | 职责 |
| --- | --- |
| 内容层 | 出身、年龄路径、事件、选项、日常、宏观与回响数据 |
| 模拟层 | 资格、人物、年度账单、时间安排、市场、事实与因果条件 |
| 播放层 | 哪些事件已读、当前滚动锚点、到哪一个关键节点暂停 |
| 视图层 | 首页、主界面、面板、选择、回顾、表单草稿与即时反馈 |
| 保存与分享 | 明确规则版本、校验、导入导出、只读回顾与选定片段 |
| 可选服务端 | 真实人数等非游戏必需能力；失败不阻止游戏 |

- 原站与 GitHub 测试版使用同一游戏和数据版本；统计能力按部署配置开启。保持原站只读旧进度的能力，新站没有账号云存档时明确说明。

- 所有样式、脚本和图片使用可适配 GitHub 项目子路径的地址。分享卡、二维码和链接基于当前 origin 与 base path 生成。

- 新引擎使用独立存档键和明确格式版本。选择、订单与回响持有防重复标记；旧链接仍由旧规则读取，不能用新规则重新推演后悄悄改变结果。

- 不承诺任何托管在所有国内网络必定可达。发布需分别检查 HTTPS、静态资源、移动端、子路径和真实朋友网络，不靠改网页文案解决平台访问拦截。

# 十五、交付与验收清单

- 首页在手机第一屏能看到主操作；有进度时可以直接继续，重开不会误覆盖。

- 三个出身同局刷新不变，选中即时高亮，确认后另两张不在历史或分享出现。

- 主界面优先显示事件，内容少时无大块空白，多时有限高内部滚动。

- 读旧记录时保持锚点，有新事件提示；后台回来不快进。

- 普通信息面板不暂停；关键选择暂停，关闭不会代选。

- 重心、持仓、余额与资格在面板内即时更新，输入草稿不因重渲染消失。

- 年度资产计划允许多项配置、万元输入、部分卖出、单独清仓和持有；一次确认不会执行两遍。

- 儿童、非大学、独身、无子女、经营者与退休者的页面文案正确，不显示不合身份的任务。

- 回响展示实际因果，没有反事实路线树和未来剧透。

- 终局没有称号、总分、排名、遗憾清单；分享先预览并真正过滤隐藏内容。

- 导入失败、断网、统计异常、存储失败和旧版进度都有可恢复状态。

- GitHub 子路径、原域名、手机浏览器、键盘与减少动态效果完成基本验证。

建议先交付手机尺寸的首页、三选一、游戏主界面和一个关键事件，再验证整套面板与回顾。不以首页视觉稿代替实际交互验收。本次仅提交站点设计文档，未修改代码或部署。
